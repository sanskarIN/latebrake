## Changes since v0.5.37

- **CHECKPOINT EPOCH on already-paused OS interruption:** Corrected a source-level race-integrity edge case. An operating system or platform can pause Unreal *before* the deactivation delegate arrives. Previously, focus loss latched but returned `false`, so GameMode could skip checkpoint-session revision invalidation.
- **Distinct decisions:** Portable `FocusLossTransition` now returns `Ignored`, `SuspendedAlreadyPaused`, or `SuspendedNeedsWorldPause`. Every first activation advances the checkpoint session revision, while only the latter requests another Unreal world pause. Duplicate OS callbacks do not create fresh epochs.
- **Safe motion continuity:** An approach sample from before loss of focus can no longer be used with a post-resume crossing from a newly latched already-paused session. A fresh approach and crossing in the resumed session remains eligible for ordinary race progress.
- **Regression coverage:** The real C++20 `AppFocusRaceGuardTests.cpp` now exercises an already-paused world with real `RaceProgress.cpp`, `CheckpointSessionTrace`, and `RaceSessionEpoch`, plus repeated deactivations, paused clock safety, explicit resume, world-pause failure and menu/finish cases. `AppFocusRaceBindingTests.py` checks the actual Unreal GameMode source ordering and new transition contract.
- **Updated device QA:** The touch-control documentation calls for explicit OS-already-paused, duplicate deactivation, and checkpoint re-baseline tests on real packages.
