## Source improvements since v0.5.32

- **Measured live sector target:** The portable `LiveSectorTarget.h` reads only the actual current-sector elapsed time and the best valid positive duration of the *same* sector in the running race.
- **Actionable source HUD feedback:** The expanded race HUD displays `Xs UNTIL PREVIOUS BEST` while a segment is still within its measured reference, or `OVER PREVIOUS BEST +Xs` after elapsed sector time exceeds that reference. This is not a predicted finished split.
- **Safety and integrity:** The target is hidden before a legitimate timed lap, after finish/reset, for invalid or missing positive sector references and for unsupported race clock values. The feature grants **no** records, credits, medals or progression changes.
- **Regression coverage:** New portable C++20 tests compile actual `RaceProgress.cpp` and test positive, zero/missing and improved split references, exact-best and overtime boundaries, different gates, finish and restart. Python source-level checks assert the Unreal HUD calls the same portable policy.
- **Public documentation:** The project website and README now clearly mark v0.5.32 as a published source-only preview and distinguish the newer v0.5.33 work from verified playable game capabilities.

## Tested scope, not game certification

The GitHub Actions source pipeline checks real engine-independent C++20 racing code on Ubuntu, Windows and macOS, Python source contracts and PowerShell packaging policy. It **does not compile Unreal Engine 5.8**, render the HUD inside the game, cook the circuit, or test installed Win64 / Android packages.

This published source snapshot includes **zero executable attachments**; the GitHub source ZIP/tar.gz archives are not playable binaries.
