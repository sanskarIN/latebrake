## Changes since v0.5.41

- **PLAYER DRIVE READINESS:** Fix a gap in the actual Unreal player pawn where menu or manual pause could freeze the race clock and checkpoints without blocking throttle/steering forces if `SetGamePaused` failed and the world continued ticking.
- **Race-state consistency:** The new allocation-free C++20 `PlayerDriveReadiness.h` checks six conditions: authoritative GameMode, ready circuit, menu closed, Unreal world unpaused, OS focus guard cleared and race not finished. If any check fails, the pawn clears raw/filtered input and touch ownership, zeroes existing chassis velocities and returns **before** applying drive force/torque.
- **Finishing and restarting:** A completed race or unavailable circuit cannot keep accelerating against frozen/blocked timing. Deliberate menu return, OS resume or an authorized race restart restores driving eligibility when all gates are clear.
- **Source regressions:** `PlayerDriveReadinessTests.cpp` verifies all 64 combinations of the six flags and explicit unpause/restart. Python checks inspect actual Unreal player-pawn source wiring and preserve existing focus-loss/touch-resume contracts.
