## Changes since v0.5.35

- **Atomic race-penalty accounting:** The real engine-neutral `RaceProgress` maintains an allocation-free count and total of successfully committed time penalties. This is *not* an extra scoring fee. The charged amount is already included in elapsed time, lap time and sector splits.
- **Fail-closed numerical policy:** A penalty cannot authorize recovery if its clock increment is undercharged, its audit total is unrepresentable, its clock would overflow or its count saturates. Rejected operations preserve clock, count and total.
- **Visible, honest telemetry:** Expanded HUD source shows `TIME PENALTIES`, the total and `ALREADY IN TIME`. The results menu also shows this included breakdown without double-counting. Compact Android HUD does not gain an extra dense row.
- **Regression coverage:** Real-`RaceProgress.cpp` `TimePenaltyAccountingTests.cpp` covers multiple/fractional charges, invalid values, finish, reset, lap/sector semantics, paused recovery rejection and extreme precision. Python source-binding tests check the HUD callsites.
- **Preserved semantics:** v0.5.35 focus-loss suspension stays intact. No career credits, checkpoint awards, saved record schemas or engine package identity change.

## Source-level verification and limitations

GitHub Actions tests the **actual portable C++20 core** on Ubuntu, Windows and macOS, Python Editor-source contracts and PowerShell packaging-policy fixtures. A separate source-only pre-release gate retests the pinned revision and checks the prior release, release tag and no-asset policy.
