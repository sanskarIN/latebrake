# LateBrake v0.5.31 — Checkpoint Diagnostic Clarity

**SOURCE-ONLY GitHub pre-release. This is NOT a playable game build.**
**No compiled Win64 EXE, Android APK/AAB, or installed playable game is included.**
GitHub-generated source ZIP/tar.gz archives are **not installers**.

## New source work since v0.5.30

- **Visible invalid physics velocity:** Non-shipping, opt-in `latebrake.CheckpointDiagnostics 2` aggregated local log lines now include the `invalid-velocity=<count>` bucket. This exposes the new trace discontinuity condition introduced in v0.5.30 and lets testers distinguish it from wrong-way, lane, height or frame-travel failures without per-frame player-position logging.
- **Backward-compatible log analysis:** `scripts/AnalyzeCheckpointQA.py` now reads both the earlier v0.5.4 aggregate log format (where the field is absent and defaults to zero) and the v0.5.31 extended format. It sums valid bucket totals and rejects malformed, duplicated, overflowing and inconsistent velocity counters.
- **Stronger verification:** Portable `GateDiagnosticCountersTests.cpp` exercises the new reported category, and Python tests cover legacy logs, new multi-window summaries, malformed fields and a source contract checking the actual Unreal checkpoint actor format.
- **Documentation site:** The full local QA logging guide, project status and release-history links remain available at https://sanskarin.github.io/latebrake/.

## Validation and limitations

GitHub Actions builds and tests the original portable C++20 source on Ubuntu, Windows and macOS, runs PowerShell packaging policy fixtures and Python Unreal Editor stubs/source contracts, and validates the documentation build. These checks **do not compile Unreal Engine 5.8** or verify real device logs.

A public source-only pre-release must contain **zero executable attachments**. Its immutable tag identifies the exact tested source revision; it does not certify a cooked map or Android/Windows game package.

## Still required for a playable game

1. Real UE 5.8 C++/UHT/editor compile and a project-owned cooked circuit map.
2. Actual running game logs at checkpoint diagnostic modes 0, 1 and 2. Inspect the new invalid-velocity bucket under controlled QA instrumentation, without treating synthetic logs as genuine evidence.
3. Installed Win64/Android driving, race scoring, pause, touch, save and crash recovery acceptance.
4. Verified package identity/provenance and a real evidence record in [issue #31](https://github.com/sanskarIN/latebrake/issues/31) and [issue #13](https://github.com/sanskarIN/latebrake/issues/13).
