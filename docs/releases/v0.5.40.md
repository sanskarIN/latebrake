## Changes since v0.5.39

- **ACTIVE LAP CLOCK:** `RaceProgress` now tracks the number of completed laps containing a genuine successful `Advance` call, independent of penalty-inclusive timed-lap counts. Only an actually representable advancing clock update qualifies; invalid deltas and recovery time charges do not create that evidence.
- **Award integrity:** The shared engine-independent `FinishTimingEligibility.h` rejects an ordered finish for awards when *any* completed lap is zero duration or entirely recovery-penalty time, or when elapsed/best/last/slowest times are not recordable. This is an additional safeguard, not proof of physical vehicle movement.
- **Authoritative integration:** Unreal GameMode consults the same eligibility rule **before** updating credits, medals, completed-race counters, personal bests or player SaveGame. Invalid results remain visibly rejected.
- **Result honesty:** Finished-race insights and HUD/results cannot present an invalid gate-complete run as an awardable timed finish. Existing valid race behavior and penalty-inclusive split timing are preserved.
- **Tests:** Portable `FinishTimingEligibilityTests.cpp` uses the real `RaceProgress.cpp` for valid 2-lap racing, zero-duration laps, penalty-only first/final laps, rejected deltas, overlong clocks, resets and a valid one-gate event. Editor source-binding checks assert real GameMode award ordering and HUD integration.
