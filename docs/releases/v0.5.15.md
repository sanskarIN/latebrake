## Racing and development changes since v0.5.8

- **Checkpoint pause, menu and restart isolation:** A single `RaceSessionEpoch` policy in GameMode prevents samples before a menu action, restart, or pause transition from being connected to samples after it. The standalone test uses actual directional gates and RaceProgress state. The first post-transition sample is a new baseline, not an earned checkpoint.
- **Quick Race/career/results transitions:** Accepted menu actions clear held input and restore race state without reusing old positions; direct restart dismisses an open menu. Rejected career replays leave previous results and save state untouched.
- **Race clock and scoring:** Subsequent source-only improvements from v0.5.9 onward require a valid local player, ready circuit, active race, and unpaused gameplay. Invalid state cannot earn a gate or advance the race clock.
- **Candidate archive integrity:** Release engineering now rejects symlink/junction traversals, dirty tracked inputs, inconsistent manifests and malformed Win64/Android package structures. Human QA evidence must identify the exact candidate-manifest SHA256; matching source revision alone is insufficient.
- **Regression coverage:** C++20 standalone tests for checkpoint sessions, authoritative race progress, save operations and driving policies; Windows PowerShell packaging negatives; Unreal editor Python stub tests.

## Verified release scope

The dedicated release workflow must compile and pass portable C++20 tests on **Ubuntu, Windows and macOS**, PowerShell negative packaging checks and editor-only Python stub tests on the same immutable `main` commit. No asset called `LateBrake.exe` or `.apk` will be fabricated or attached. The version tag is never moved if one already exists at another commit.

**This is NOT a playable game build.** The authorized Unreal Engine 5.8 Editor/UHT/game build, genuine binary `Content/Maps/LatebrakeCircuit.umap`, Cook/BuildCookRun, installed Win64 and Android playtests and hardware UI/collision/physics tests remain **UNVERIFIED**. Source policy and simulated negative logs cannot prove that the game is working on devices.

## Steps still required for a playable version

1. On a properly licensed Windows workstation, compile Unreal Engine 5.8 Editor and game targets and save an actual circuit map using Unreal Editor.
2. Cook and package genuine Win64 and Android candidates; keep the exact artifact and candidate manifest hash.
3. Install those candidates and verify lap timing, directional checkpoint order, menus, HUD, save data, recovery, collision, rival and touch controls on the supported devices.
4. Record real QA and evidence on [checkpoint issue #31](https://github.com/sanskarIN/latebrake/issues/31) and [Android issue #13](https://github.com/sanskarIN/latebrake/issues/13) before calling any build playable.
