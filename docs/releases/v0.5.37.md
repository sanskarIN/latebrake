## Changes since v0.5.36

- **Honest lap penalty attribution:** The engine-neutral `RaceProgress` tracks what portion of already-paid time penalties occurred on the current lap and on the last completed lap. The original event total, official elapsed time, sector timing and lap record semantics stay unchanged.
- **Ordered boundary only:** A new last-lap penalty snapshot is taken only when the actual final checkpoint for that lap is accepted. Partial sectors cannot reset it. The next lap begins with zero current-lap fees, even if older laps incurred recovery penalties.
- **Useful HUD feedback:** In the expanded source HUD, `THIS LAP PENALTIES` appears only after a positive charge in the unfinished lap; results menu shows `Final lap penalties included` where appropriate. The labels explicitly say the fees are included in lap/race time, not new fees.
- **New regression gate:** Portable `LapPenaltyAttributionTests.cpp` links the actual `RaceProgress.cpp` to verify multi-lap attribution, penalty-free laps, multiple fees, malformed/rejected attempts, completed races, resets and one-sector races. Python source contracts verify HUD callsites.
- **Compatibility:** Existing v0.5.36 atomic total accounting and v0.5.35 focus-loss suspension remain intact. No additional persistent profile fields, rewards or assets are introduced.
