## Source improvements since v0.5.20

- **Global invalid-viewport fail-safe:** Portable `TouchDriveState` now clears the *previous* throttle, brake and steering owners if an input press arrives while the viewport geometry is invalid, e.g. during a screen orientation/size change.
- **All move finger IDs:** An invalid layout also clears held controls when the move event's finger ID is negative. The incoming touch cannot claim controls, and late move events cannot reacquire canceled steering or throttle.
- **Regression tests:** `TouchDriveStateTests.cpp` and `TouchFingerRangeTests.cpp` cover existing held gas+steering, invalid press and move events, negative and untrackable finger IDs, and stale move rejection after cancellation.
- **Existing features retained:** The v0.5.15 checkpoint session fixes, v0.5.16 shared 16-finger bounds, v0.5.17 lap-pace HUD forecast, v0.5.18 rival readiness, v0.5.19 finite rival recovery budget and v0.5.20 monotonic lap history remain in source.
