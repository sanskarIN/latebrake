## Implemented source

- Four independent contact-phase rotor models use actual road-point speed,
  spring-projected normal-load estimates and explicit SI conversion.
  Implicit tire-slip integration and static brake complementarity have
  bounded work and modeled energy checks. Every output remains beneath
  that corner's existing admitted road-tangent force ceiling.
- Modeled service pressure uses an admitted-torque feed-forward ceiling,
  slip hysteresis and hold timing. Mechanical rear locking bypasses that
  controller, including with both pedals held. Heat scales effective
  service torque. Six fictional garage profiles have original candidate
  inertia, torque and slip settings, not manufacturer specifications.
- Unique delivered-frame receipts prevent stale, rejected, orphan or
  double-settled proposals from advancing modeled wheel work. Independent
  decorative wheel phases consume the committed angular integral.
- Development telemetry explicitly identifies modeled rotor speed,
  pressure and slip, estimated normal loads and commanded tire forces.
  A strict versioned reader checks schema, actor identities, finite fields,
  passive command power and conservative load bounds. It cannot certify
  actual Unreal execution or measured tire forces.
- A service-brake capability estimate reuses the accepted spring/road
  frame and actual brake settings. It reserves force, rotor equivalent
  mass and a worst-direction measured-grade allowance. The shared pawn
  publishes it only after accepting its complete drive frame.
- Rival corner planning rejects stale/pre-teleport capacity, lowers its
  forecast immediately on capacity loss and restores it gradually across
  fresh frames. Reaction-distance allowance and the actual incoming
  segment constrain the existing gate forecast. Zero capacity removes
  propulsion. No checkpoint, lap, reward or save authority is added.

## Source qualification

Publication must build and run the complete strict C++20 CTest suite on
Windows, Ubuntu and macOS at the exact source pin; all Python source/editor
checks, PowerShell syntax/synthetic packaging policies, Node release guards
and rendered-documentation checks must pass. Named rotor, four-corner,
visual, capability and rival-approach tests must actually be present.
Only logs for that source pin establish the final counts.

Regressions include 100,000 randomized rotor-energy cases, 12,000 mixed
four-corner frames and 25,000 capability frames. The six-profile synthetic
flat stop varies by less than 0.02% across 30/60/120 FPS in its fixed-mass
harness. Another 108 prescribed flat approaches compose the actual wheel
model and capacity-aware rival forecast across six cars, two modes, three
grip/heat/load conditions and those frame rates. These harnesses do not
reproduce complete in-engine vehicle configurations, collisions or races.

The interim 100,000-line source target and the v0.6.0 **200,000 nonblank
noncomment production C++ line** target remain unmet. Tests, docs,
workflows, build rules, generated/vendor code and padding do not count.
Source volume never establishes handling quality or playability.
