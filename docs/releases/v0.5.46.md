## Changes since v0.5.45

- **VERIFIED RECOVERY:** The actual Unreal player RECOVER path no longer charges five seconds before blindly moving the pawn. A rejected, partial, nonfinite or misoriented physical teleport does not commit a recovery fee or recovery count.
- **Production C++20 source files:** `RecoveryTeleportVerification.h` and `RecoveryTeleportVerification.cpp` evaluate Unreal's actual `SetActorLocationAndRotation` return status, the resulting 3D location (within 5 cm of requested destination) and yaw (within 2°, allowing equivalent wrapped angles). Returns typed reasons for denied or invalid placement.
- **Checked Unreal pawn API:** `ALatebrakeCarPawn::TryRecoverTo` rejects nonfinite target poses, invalidates all checkpoint trace generations *before* any movement attempt, neutralizes live input/physics, calls `ETeleportType::TeleportPhysics` and validates the observed transform. Existing Blueprint-facing `void RecoverTo` remains compatible for restart and rival recovery.
- **All-or-nothing racing transaction:** `TryChargePlayerRecoveryAfterVerifiedTeleport` stages the complete five-second fee against a temporary copy of the fixed-size `RaceProgress` and recovery count. Only a verified successful move commits elapsed time, penalty audit and recovery telemetry. Circuit readiness, app/manual pause, race-finished status, full-fee numeric precision and counter overflow are still enforced.
- **Regression and qualification:** `RecoveryTeleportTransactionTests.cpp` compiles both production `RecoveryTeleportVerification.cpp` and actual `RaceProgress.cpp` on three OS CI; tests rejected/misplaced moves, wrong yaw, NaN/Inf, legitimate success and retry, zero charge on failure, overflow and checkpoint re-baselining. Python Unreal-source contract tests check actual GameMode and pawn wiring. See `docs/VERIFIED_RECOVERY_QA.md`.
