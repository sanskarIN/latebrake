## Changes since v0.5.42

- **MANUAL PAUSE FALLBACK:** A standalone ESC, controller or Android PAUSE press now sets a dedicated engine-independent `ManualRacePauseGuard` latch **before** calling fallible Unreal `SetGamePaused(true)`. If Unreal continues ticking without pausing, competitive race timing and scoring remain blocked instead of continuing behind an unacknowledged PAUSE request.
- **Consistent race-state lockdown:** Every relevant Unreal source consumer observes the fallback—GameMode elapsed clock, ordered checkpoint awards, paid recovery, checkpoint motion sampling, autonomous rival, player chassis force/torque, driving touch dispatch and HUD display. The HUD shows PAUSED even when the Unreal world is not paused.
- **Clean manual resume:** A genuinely new PAUSE press, deliberate return from menu or accepted race restart may clear the manual latch. Application foreground notifications alone cannot resume racing. Both failed PAUSE and later manual resume advance checkpoint motion-session generation so old gate approach points cannot score after resumption.
- **New regressions:** `ManualRacePauseGuardTests.cpp` integrates the real `RaceProgress.cpp`, checkpoint session trace, focus guard, recovery, rival and player readiness to simulate rejected engine PAUSE/UNPAUSE. Python source-binding tests require the latch in all actual Unreal C++ call sites. The older focus-policy mutation test is updated to validate the combined guard.
- **Device QA instructions:** Expanded Android touch testing instructions include normal pause, controlled denied `SetGamePaused` and resume/focus-loss scenarios.
