## Improvements since v0.5.92

### Opposite-pedal and sideways-slide recovery
- Classify engine braking using the **measured signed longitudinal speed**.
  A vehicle moving almost entirely sideways can still request drive torque
  without falsely activating opposing-direction braking.
- Keep actual opposite-pedal braking when the signed forward/reverse motion
  really opposes the command; preserve rear-axle traction, grip and
  service-brake precedence.
- Avoid charging engine heat for throttle input that the opposing-brake
  policy explicitly prevents from reaching the motor. Cover forward and
  reverse regression scenarios at 30, 60 and 120 FPS.

### Physically delivered drafting HUD
- Report only the drafting motor-force fraction that survives the same
  shift, rear-wheel load, surface, collision damage, engine heat and
  traction limits used for the real force submission.
- Preserve the original nitro/drafting shared budget, race authority,
  lap/checkpoint validation and saved progression.

### Inspectable handling evidence for a future installed game
- Add bounded **non-shipping** `LATEBRAKE_DRIVE v=1` diagnostics using
  the existing suspension event cadence: signed driving speeds, yaw,
  throttle/steer input, loaded axle limits and actual branch-authorized
  motor, service/opposite braking, lateral and yaw force requests.
- Add strict offline `scripts/AnalyzeDriveTelemetry.py` validation of
  malformed/contradictory force records. These are **requested forces**,
  not measured Chaos acceleration or independently proven driving feel.
- Add a `drive-audit` command to
  `scripts/Review-WindowsPlaytest.py`. It binds the *exact* log bytes to
  a schema-2 runtime receipt and the complete SHA256-checked Win64
  candidate, engine Build.version, original map and source commit.
  `--require-player` rejects logs containing only autonomous-rival
  samples. Reports always state `gameplay_verified: false` and
  `ready_for_release: false`; editable files and matching hashes do
  **not** authenticate a real playtest.
- Expand source-only unit tests and Windows physical driving acceptance
  guidance without introducing extra shipping physics or runtime features.

## Verified scope and strict limits

The exact reviewed source must independently pass **184 C++20 CTests
on each of Windows, Ubuntu and macOS**, **674 Python source/fixture
tests**, PowerShell packaging-policy checks and the complete
documentation build. These checks establish source behavior and safe
test fixture interpretation only. The publishing workflow must repeat
the checks for the exact candidate SHA before making the source
pre-release visible.

**None of this is a successful Unreal Engine 5.8 Editor/UHT/Game build,
a genuine cooked circuit, installed Win64 racing, rendered graphics,
Android device QA, calibrated tire physics or a verified game installer.**
The prototype still uses a rigid Chaos chassis with experimental
four-corner ray springs; it is not a finished AAA racing game.
